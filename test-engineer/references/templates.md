```markdown
## 定级

- **P0 阻断**：测试使用真实生产凭据或未脱敏 PII；安全路径（鉴权/会话/密码处理/令牌签发与解析/加密/敏感数据访问）的测试 mock 掉被测逻辑、删掉断言**或从未写过断言**（三者等效）形成假绿；门禁被系统性绕过且鉴权/金钱/数据完整性路径无有效验证（**"绕过"需要门禁存在的证据——存在 CI/门禁配置但被 continue-on-error、allow_failure 等架空才算；从未建过门禁不算"绕过"，按 P1"门禁不存在"处理**）；测试产物与当前代码版本不对应，却被作为验证通过的证据（只评"对应关系不成立"这个客观事实，不评动机）。**"被作为证据"的取证三选一**：该产物已被 git 提交 / 被 CI 配置引用 / 被文档、README 或提交信息引用其中数字——任一成立即算；仅位于标准报告路径（surefire-reports/、coverage/ 等）但未提交、无人引用时**降 P1**，并注明"是否被采信无法核实"。

- **P2 一般**：有明确改法的确定性改进项。
- **P3 建议**：风格与优化。
- 违反契约硬性条款最低 P1，同时触及安全或数据完整性升 P0，P0 封顶。无契约项目按检查点严重性定级。

## 铁律

- **只读、不执行测试**：不修改任何文件；不运行测试命令（`npm test`/`pytest`/`mvn test`/`go test`/`playwright test` 等）、不带动覆盖率开关重跑、不装依赖、不起容器、不写快照；**不用 `--collect-only`/`--listTests` 枚举测试**（会 import 模块触发副作用）。只允许：列目录、搜内容、读文本与报告产物、只读 git。
- **证据强制**：每条计入统计的发现给 `文件:行号` + 片段；**否定性发现（应存在而查无，如"CI 配置穷举 0 命中""错误码在测试中命中 0"）用 `搜索式 + 范围 + 命中数` 呈现即可，不要求行号**；靠外部系统才能确认的进「未决项」，不计入统计。
- **证据不可得 ≠ 未发现**：查过没找到写"未发现"；没法查写"证据不可得"。后者是缺口不是结论，不得混入"未发现"，也不得据此下"可发布"判断。
- **一条发现可挂多个维度**：同一段代码同时构成"mock 掉被测逻辑 + 断言实现细节"时，维度写 `1、2、5`，不要只挑一个。
- **不适用须给依据**：只有两种合法依据——项目形态不适用（写明形态），或该模块零测试（须指向维度 11 的具体发现编号）。无依据的"不适用"视为未覆盖。
- **不虚报**：零发现就写"未发现"，不为凑数抬级或降级。
- **覆盖深度如实标注**：审不完时优先深审高风险区（鉴权、金钱、数据完整性、异步、外部依赖相关测试），快扫范围写进报告头部。

## 报告

<嵌入下方「子报告模板」，含目标文件名>
<若你同时负责多份子报告：每份单独成文、单独落盘，各自满足维度闭环与证据要求，**不得把两份并成一份或互相引用代替内容**>

## 完成标准

- 所辖 `<N>` 维每维都有结论（有发现 / 未发现 / 不适用+依据 / 证据不可得），四者相加 = `<N>`。
- 计入统计的发现证据可定位。
- 未执行任何测试，未修改任何文件。
- 报告写入 `<输出目录>/<NN-主题>.md` 并自查通过；不得写入被审仓库内。
```

```markdown
## 结论

<一段话：这些测试值不值得信任、最突出的风险主题、指出哪些"看起来有测试"的地方其实是假绿。>
"先补哪三个"的取法：**按 Top 问题排序取前 3，P0 优先**；不足 3 条就列实际数量。**Top 为空（零 P0/P1）时**：从 P2 按影响面广度取至多 3 条，**级别如实标注**——这不是"把 P2 抬上来"（抬级指虚标级别，如实写 P2 并入选是允许的）；P2/P3 也为空就写"无——本次未发现需优先处理的问题"。**判「证据不足」时**：有已查实问题（P0/P1 中不受证据缺失影响的部分）仍按 Top 取前 3；Top 为空（问题全被证据缺失盖住）才改为「先补哪三样证据」，见下方例外。
**混合模式例外**：三件事**两账合并排序**——06 报告有 P0 系统缺陷时排第一（写"修复系统缺陷 <标题>，详见 06 报告缺陷 DEF-01"），其后**按 P 级合并排序（同级时系统缺陷优先于审计发现）**；审计账为"证据不足"变体时，"先补哪三样证据"排在系统缺陷修复之后。否则用户会看到"先补三个测试资产问题"，而实际最该修的是越权。
**例外**：判「证据不足」**且 Top 为空**时，此处改为「**先补哪三样证据**」，与收尾回复的证据不足变体对齐；Top 非空（有查实的 P0/P1）时仍按前 3 条问题填，不要因为整体证据不足就丢掉已查实的问题。
```
