# 32 个评审维度：6 大聚簇与通用检查点

> 通用工程标准，适配任意语言与栈。派发子代理时摘录对应聚簇进自包含指令；
> 若目标项目存在成文契约（AGENTS.md / CLAUDE.md 等），先逐条对照契约——**契约条款违反最低 P1，触及安全或数据完整性升为 P0**（与 SKILL.md 铁律 3 一致）；
> 检查点应按目标栈等价换算（如通用"事务"在 JVM 项目换算为事务边界、ORM 行为、锁与隔离级别；通用"路由"在前端项目换算为路由守卫与权限校验）。
> 逐维结论四态：**有发现 / 未发现 / 不适用+依据 / 证据不可得+缺什么**。判定优先级 **有发现 > 不适用 > 证据不可得 > 未发现**：部分证据缺失但已查实问题时归"有发现"（在自查表结论单元格内并列标注缺什么，如"有发现；CVE 子项证据不可得"）；形态上不适用优先于证据缺失（根本不该去查）；只有既无发现、又不适用、且证据齐备时才写"未发现"。**「不适用」必须给依据**，只有两种合法依据：① **项目形态不适用**（如零付费服务评维度 22、零外部依赖评维度 9、纯库不部署评维度 21）；② **无评测对象**（如项目无定时任务评任务可重入）。无依据的"不适用"视为未覆盖——禁止强行评（虚构问题）或写"未发现"（沉默冒充清白）。需要外部数据而本地拿不到的子项归"证据不可得"，写明缺什么，进待核实区——不得写成"未发现"（与 SKILL.md 铁律 2 一致；**四态按子项标注、可组合**：同维本地有发现、个别子项需外部数据或形态不适当时并列标注）。**恒等式按维度主结论计**（判定优先级最高的那一类）；子项级证据不可得只进子报告统计行与待核实区，不进 32 维恒等式，主会话在汇总「覆盖深度与未覆盖说明」以"维度 N（部分子项：<...>）"体现。
> 每个聚簇标注的「降级优先级」供子代理失败降级时使用：主会话按此顺序亲审；**未列入降级优先级的维度在降级时统一标记为「未覆盖」——「未覆盖」不是第五态，它归入"证据不可得"，原因是"评审降级未审"**（与"资产缺失失效"并列分列，两种原因都计入证据不可得、计数不变）。

## 聚簇 A：正确性与可靠性（7 维）

> 降级优先级：缺陷 → 并发 → 静默失败 → 幂等与一致性

1. **缺陷**：逻辑错误、反转条件、差一错误、NPE/空引用、资源泄漏（连接/流/句柄未关闭）、错误的异常路径。
2. **功能**：实现与需求/接口契约的一致性——逐端点/逐用例对照 API 文档与 PRD；返回结构、错误码、状态码与契约不符；未实现或 stub 化的承诺行为。
3. **边界**：空集合/空字符串/null、极值与溢出、分页参数越界、非法输入未校验、字符集与时区边界、大小写与编码。
4. **并发**：竞态与 check-then-act、共享可变状态无保护、事务边界过宽或过窄、隔离级别不足、锁粒度与死锁、双写不一致、异步任务对共享资源的并发访问。
5. **静默失败**：吞异常、空 catch、降级无日志、离线/队列数据无提示丢弃、失败不告警不重试直接当成功、`catch` 后返回默认值掩盖真实错误。
6. **幂等与一致性**：重复请求/重试是否产生副作用、幂等键与唯一约束兜底、缓存与库的一致性（先落库再删缓存的次序）、部分失败后的数据一致性、并发下的丢失更新。
7. **超时重试与降级**：外部调用（HTTP/DB/缓存/模型）是否设超时、重试是否幂等且带退避、下游不可用时是否回源且不阻塞主链路、降级路径是否真的可用、熔断缺失。

## 聚簇 B：安全与合规（3 维）

> 降级优先级：安全 → 数据隐私与合规 → 供应链安全

8. **安全**：越权路径（水平/垂直越权、IDOR）、服务端鉴权缺失（前端隐藏≠权限）、注入（SQL/命令/模板/反序列化）、密钥硬编码或入日志、会话与 token 生命周期（过期、轮换、吊销）、CSRF/XSS 面、审计缺失的敏感操作。
9. **供应链安全**：依赖已知漏洞（CVE）、来源可靠性、传递依赖风险、锁文件完整性、镜像与构建来源、废弃/停止维护的依赖。**CVE 查证需要外部漏洞库**（NVD/OSV/GitHub Advisory）：无网络或查证不可行时，**降级为本地启发式检查**（依赖版本是否明显陈旧带已知大版本漏洞、锁文件是否存在且完整、废弃依赖标记），并把"未做完整 CVE 比对"按「证据不可得」标注（处理规则见 SKILL.md 铁律 2），不得写"未发现漏洞"。
10. **数据隐私与合规**：PII 与敏感数据的存储/日志/导出路径、日志脱敏（密码/token/完整业务数据）、数据可见性规则（谁能看什么、批量导出限制）、软删与留痕是否符合声明。

## 聚簇 C：架构与设计质量（6 维）

> 降级优先级：设计合理性 → 架构对齐与可演进性 → 代码库一致性

11. **设计合理性**：职责划分（上帝类/贫血/层次错位）、抽象是否贴合问题、循环依赖、接口契约与实现的一致性、错误处理策略统一性。
12. **过度设计**：为"专业感"引入的抽象/分层/模式、只有单实现的接口体系、无演进计划的通用化、推测性配置项。
13. **架构对齐与可演进性**：与项目声明的架构约定冲突、与现有风格格格不入的新写法、阻碍后续迭代的耦合点、模块边界被侵蚀。
14. **代码库一致性**：相似场景写法一致（错误处理、返回结构、命名、分页、时间处理）、同一概念多种表示、复制粘贴漂移。
15. **技术债**：半成品与 TODO 长期滞留、绕行写法、迁移过渡代码未收口、注释与现实脱节、死代码。
16. **可测试性**：依赖不可注入、时间/随机/环境硬编码不可控制、静态单例阻碍测试、测试需要真实外部服务才能跑。

## 聚簇 D：性能与可运维（6 维）

> 降级优先级：性能 → 可观测性 → 回滚与发布安全

17. **性能**：N+1 查询、循环内查库/调用、缺失索引的可疑查询（在实测前提下评估，不臆断）、无界结果集、重复计算、缓存命中率与击穿/穿透/雪崩、大对象拷贝。
18. **可观测性**：traceId 贯穿、关键路径日志级别恰当、脱敏字段完整、审计切面覆盖全部应审计写操作、错误日志可定位（含上下文）、指标缺失。
19. **可运维性**：健康检查覆盖依赖、定时任务可重入/可恢复、优雅停机、清理任务与保留策略落地、配置热更新或重启路径明确。
20. **环境可移植性**：环境差异处理（local/prod 的 fail-fast 行为）、硬编码路径/域名/本机值、容器与非容器行为一致、对文件系统/时区/ locale 的隐式假设。
21. **回滚与发布安全**：迁移可回退性、破坏性变更（删列/改类型/改语义）、新旧版本共存兼容、启动失败模式（fail-fast vs 带伤运行）、灰度路径。
22. **成本影响**：不必要的重复外部调用（模型/API/付费服务）、缓存未利用导致的重复计算、日志量失控、资源规格浪费。

## 聚簇 E：规范与风格（3 维）

> 降级优先级：命名风格 → 代码格式 → 依赖治理

23. **代码格式**：项目声明格式化工具（google-java-format / biome / prettier 等）合规、Javadoc/注释规范（项目要求哪种语言、@param/@return 等）、注释讲"为什么"而非复述代码。
24. **命名风格**：对照项目命名文档（如 NAMING.md）；无文档时按语言主流惯例：包/目录结构、类型后缀约定（Impl/Dao/Service/Repository 等）、标识符拼写、英文错误码与日志字段名。
25. **依赖治理**：新增依赖是否在项目白名单或已说明理由、重复功能的多个库、未使用依赖、版本过旧或过新（无生态支持）、scope 泄漏（编译期依赖进运行时）。

## 聚簇 F：需求与交付质量（7 维）

> 降级优先级：需求覆盖与范围保真 → 缺失项审计 → 测试有效性与验证证据

26. **需求覆盖与范围保真**：PRD/API 文档承诺但代码缺失的端点与行为、做了但没被需求要求的功能（scope creep）、验收标准逐条可对上。
27. **接口与配置兼容性**：对外 API 变更是否破坏调用方（字段增删、语义变化）、配置键重命名/失效、默认值变化、序列化格式兼容。
28. **测试有效性与验证证据**：测试是否真验证行为（断言强度、不 mock 掉被测逻辑）、测试与实现同构复读（无信息量）、覆盖矩阵缺口（端点↔测试映射）、测试数据代表性、集成测试覆盖主链路；**验证是否实际执行过**——变更/模块对应的测试是否可独立运行、CI 或本地是否存在可查的通过记录（只读核验，不要求评审时运行）、未运行验证的原因是否有记录、"完成"是否以验证实际通过为据而非自述。**边界声明：本维为浅扫**——只核验测试资产的存在性、断言形态、执行痕迹与覆盖矩阵映射的存在性（端点↔测试映射查缺，不做覆盖率口径深算与假绿全量记账）；需要按测试维度系统深审（假绿清单全量记账、覆盖率口径与门禁判定、主动测试实测验证）时，在报告结尾注明"建议主会话/用户转用 test-engineer skill"（**转用是主会话层面的建议动作，子代理自身不转**，照常完成本维浅扫）。
29. **影响面分析**：每个发现评估并写明波及范围（调用方、数据、下游任务、前端）、改动扩散路径、是否影响兼容性承诺。
30. **评审闭环**：每个发现有明确整改路径与登记位置建议（该进 backlog、该开 issue、该改契约文档）、无法整改的显式说明原因。
31. **合入条件明确性**：项目 DoD 是否可判定、验收清单是否可执行、"完成"定义是否模糊（无测试/无文档同步的完成）。
32. **缺失项审计**：契约/文档/配置声明了但代码缺失的东西——端点、校验、开关、测试、迁移、监控；专门扫一遍"声明与现实"的差集。
